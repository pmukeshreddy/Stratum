# Buffalo root execution architecture

Buffalo's root action loop is its adaptive policy. The model receives the task, committed trajectory, tool/verifier results, child findings, the merged harness digest and remaining resources. It answers or calls `ipython(code)`, observes the result, and chooses its next action. There is no preliminary execution-mode inference, classification schema, decision injection or reconsideration API.


```text
Task → root model → answer or IPython action → evidence → next root model turn → final
                           └→ await rlm(...) → persistent asynchronous child
                                                    └→ findings → root's later context
```

`Runtime._run_turn` owns action execution and complete assistant/tool-block commits. `_invoke` starts/restores the session kernel, performs context management when needed, assembles current inputs and makes the ordinary agent request. Existing fixed/role-based provider routing chooses configured model identities; it does not inspect task IDs, prompt length or file counts to choose actions.

A final text response in the Python autonomous mode requests completion. Configured task verifiers can reject an incorrect result. Optional waiting for already admitted children, persistent goals and interactive yielding retain their existing lifecycle semantics. No completion rule requires any Python execution, child, recursion depth, message, evidence-use count, memory, skill or refinement edit.

The exact fresh-root foundation used for live validation is in [root-foundation.txt](root-foundation.txt). It is generated by `context.python_instructions`; capability restrictions determine the available API instructions; learned state never rebuilds that prefix. The separate environment instructions and all original task messages remain in the full captured first request. Direct reasoning and direct completion are explicitly valid.

## Canonical recursive computation

The canonical Python implementation is `kernel_api.Recursive.__call__ → Recursive.run → Host.acall("rlm.run") → host_api.dispatch → Runtime.spawn_async → Runtime.spawn → Store.create`. `CodingAgents` inherits this implementation and adds candidate inspection/application only. The obsolete synchronous worker `rlm` override was removed. The older explicit-tool control plane's aliases now adapt to the same host admission implementation; they do not own another runtime.

Admission checks permissions, depth, child count and shared resources; resolves optional model/thinking overrides; accepts a task composed from any learned delegation specification; and creates a stable child session. Shared admission returns directly. Isolated workspace preparation may take time before successful admission, but admission never waits for child model execution or its answer. The scheduler independently selects runnable sessions with global and task concurrency limits. Parent work can overlap child model calls and Python execution.

A child owns its context, kernel namespace, durable history and session identity. It inherits the effective model, reasoning, workspace policy, adapter, registered capabilities and resource limits. The immutable original task contract is available separately from the delegated assignment. Descendants call the same `rlm()` implementation within shared limits. Completion unloads a child kernel after checkpointing; a later parent message reactivates the same child and restores its state rather than creating another session.

`agent_message.send` routes through host dispatch to `Runtime.message` and `Store.send`. `Store.receive` commits messages to the recipient's context at a safe turn boundary. `_invoke` drains boundary messages again after asynchronous preparation/review/compaction and immediately before assembling the request. Findings arriving during those operations therefore reach the next model invocation; ordinary idle-only follow-ups keep their existing delivery policy. Completion messages contain actual child result text. `agent_observe.recent_messages` reads committed trajectory records through `Store.trajectory`; it excludes an unfinished assistant/tool block and can retrieve historical work after compaction/restart. Follow-ups preserve the same child ID, history and Python values.

Failures need no separate replanning operation. `_verify` appends the actual verifier result to normal context; Python/tool failures appear in committed results. Messages received after a candidate answer cause a further ordinary turn. The next root request can correct code, inspect more data, test again, start useful independent work, or finish.

## Exact Python surface and call semantics

All rows below describe runtime objects preloaded by `kernel_worker.Worker` and `kernel_api.bootstrap`, without imports or client construction. Host operations retain the session identity, permission envelope, action journal and resource accounting. An async call waits for its stated operation, not necessarily for the background work that operation starts. Host validation/permission failures cross the bridge as `RuntimeError`; Python signature/type checks can raise `TypeError` or `ValueError` before dispatch.

| API and canonical example | Arguments and exact return type | Persistence, waiting and errors |
|---|---|---|
| `task.instructions`, `task.messages`, `task.assignment`, `task.context`, `task.workspace` | Frozen `TaskState`; `instructions: str`, `messages: tuple[dict,...]`, `assignment: str`, `context: Record`, `workspace: Path` | Immediate data. `messages` preserves complete original roles/order/content; `instructions` is the final original user instruction, not the whole multi-message contract. Context contains root ID, adapter and specification. Assignment and workspace belong to this session. Rebuilt from durable metadata after restart. |
| `workspace / 'input.json'` | `pathlib.Path` for the session workspace | Normal synchronous Python path operations. Child isolation changes its workspace path, not its original task. Ordinary filesystem errors apply. |
| `worker = await rlm('Inspect edge cases.', name='reviewer')` | `prompt: str`; optional keyword `name`, `model`, `thinking`, `purpose='shared'`, `isolate=None`, `adapter`, `spec_id`, `requirement`. Returns frozen `AgentHandle(session_id: str, name: str, session_dir: str, model: str)` | Returns after admission. Never returns a child answer. Stable handles survive checkpoints. `purpose` selects a registered child workspace/capability profile; omit it for ordinary shared work, and put prose in `prompt` or `requirement`. Coding accepts `shared`, `research`, `review`, `candidate`, `test`, `performance`; other adapters expose their own profiles. Unknown profiles fail explicitly. `model` uses an authenticated `provider/model` selector; names must be unique among siblings. Invalid specifications, unavailable models, permissions, depth and shared budgets can reject admission. `rlm_child_id` is an identity property on the same handle. |
| `await agent_message.send('finding', receiver_role='parent')` | `message`, optional `broadcast_message`; keyword `receiver_role`, `receiver_name`. Returns `{'receipts': [{'message_id', 'recipient_id', 'deliveryStatus': 'queued'}, ...]}` | Waits for queue admission only. Child/sibling receivers require names; parent does not. `send('all', text)` broadcasts within the authorized family. Missing/ambiguous recipients fail. |
| `await agent_message.receive()` | No arguments; `list[dict]` of newly consumed mailbox rows: ID, sender, recipient, body, creation/receipt times, source event, delivery policy and causal request ID | Returns immediately after consuming pending boundary messages; also adds them to later model context. Does not wait for new messages. |
| `await agent_message.list_agents()` | `{'self': id, 'parent': list, 'children': list, 'siblings': list}` | Current related-session metadata; no model inference. |
| `await agent_observe.recent_messages(worker.session_id, limit=8, max_chars=800)` | Target ID/name/unambiguous suffix; `limit=1..50`, `max_chars=80..2000`. Returns `{'session_id': id, 'messages': list[trajectory_record]}` | Reads committed evidence; never waits for child completion. Records carry source ID, sequence, timestamp, session, event type, role and bounded body. Invalid/inaccessible/ambiguous targets fail. |
| `await agent_observe.get(worker.session_id)` | Target as above; `{'agent': session_record}` | Current lifecycle/configuration metadata. `list_agents()` returns `{'agents': [...]}`. `requests(target)` returns the authorized request graph with requests and edges. |
| `await agents.wait(seconds=10)` | `seconds`; `{'waiting_seconds': seconds, 'wake_on_message': True}` | Returns a receipt immediately and defers the next model turn. End the cell afterward to release its slot. Message arrival or deadline makes the session runnable. This is not a blocking mailbox receive. `agents` and `rlm` are the same recursive API object. |
| `entry = harness.get('memory', id)` | `kind`, `id`; optional `global_=False`, `version=None`. Returns attribute-accessible `Record` | Synchronous host call. Missing entries raise `KeyError` locally. Records are data, not awaitables. Full content stays in Python unless inspected. |
| `harness.list(kind=None, global_=False)` | Returns `list[Record]` | Synchronous retrieval, filtered by kind and local/global scope. |
| `skills.list()` / `skills.load(name)` | List of installed skills; load returns an imported `ModuleType` | Synchronous. Importable modules are added to the namespace. Missing or disallowed skills fail. Read the associated instructions. |
| `catalog = tools.catalog()` | List of admitted function schemas | Synchronous discovery into Python. `tools.call(name, **arguments)` is synchronous; `await tools.acall(name, **arguments)` is async. Both return the tool's schema-specific Python value and execute once. Use the latter when coordinating asynchronous work. |
| `job = bash(command, cwd=None, timeout=None)` / `result = await bash(command)` | Synchronous start returns `BashHandle(id)`. Await returns `Record`: process identity, command/cwd, state/running, exit code, duration, stdout/stderr/output, stream artifact IDs, passed/timed_out/interrupted flags | Start waits only for process admission. Retaining a handle allows background work; awaiting waits for completion. Nonzero exits are results, not exceptions. `poll()` returns `None` while running, otherwise status; `tail(n=50)`, `output()`, `pid`, `running` inspect; `kill(sig=15, grace=.5)` returns status. Restart retains identity but does not silently replay a lost process. |
| `await compact()` | No arguments; `{'event_id': id_or_None}` | Compacts committed model context now, queues an automatic review checkpoint when appropriate, and retains Python state/history. Does not compact the currently executing unfinished block. |
| `await refine.run(instructions=None, global_=False)` | Returns `scheduled` immediately | The host plans and applies at a completed-turn boundary; `refine.status()` reports pending/in-flight work. |

Other generic preloads are `Path`, `pathlib`, `os`, `asyncio`, `json`, `session`, `context`, `history`, `artifacts`, `mcp`, `goal`, `verify`, `heartbeat`, `forget`, `remember_recipe`, and IPython's `get_ipython`. `shell` aliases `bash`. Coding sessions additionally preload `repo`, `git`, `edit`, `tests`, `build`, `lint`, `typecheck`, `bench`, `experiment`, and coding context/child helpers where admitted. These are capability surfaces, not an ordered workflow. Their live `help` and admitted schemas expose exact method arguments. Existing synchronous coding-capability result wrappers remain optionally awaitable; the canonical examples use their synchronous form. Plain harness/skill records do not use that compatibility behavior.

## Automatic refinement

The continual harness uses `harness_state.json` as its only active learned state,
with `prompt`, `memory`, `skill`, and `subagent` entries. Global files live under
`DATA/harness/`; session-local files live under `DATA/sessions/SESSION_ID/harness/`.
Each scope appends refinement records to `refinements.jsonl`. Existing SQLite
learned state is imported once; old tables have no runtime readers or writers.

`await refine.run()` schedules local refinement; optional instructions focus the
planner, and `global_=True` explicitly requests global changes. `await refine.status()`
returns `pending` and `in_flight`. Application runs at a completed-turn boundary,
then a durable `[self-refinement]` or `[auto-refinement]` notice informs the root
before it continues. Zero-edit proposals produce no update notice. Automatic review
is enabled at 25 turns and compaction, with a 20 minute cooldown. Failures and child
findings are ordinary trajectory evidence, not separate refinement triggers.

A compact merged digest enters context at session start, resume, compaction, and
stale-state detection. Unchanged digests are deduplicated. The base system prompt
stays unchanged after learning. Colliding global/local IDs remain visible with
scope labels; local guidance can override global guidance within the session.
Skills reference existing Python callables and their argument contracts; reusable
subagent specifications execute through native `rlm` delegation.

See [the source/test parity matrix](continual-harness-parity.md) and
[the deterministic session trace](continual-harness-trace.json).
