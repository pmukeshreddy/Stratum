This audit supersedes the first-pass conclusions about manual refinement, compaction checkpoints, auxiliary graph membership, and state visibility. It compares executable code after the second pass against the September 7, 2026 the reference source extracted at the external reference checkout from the archived source ZIP (SHA-256 `18edd31aa8bf1bb2765953328c4cffbab56fa56f2783027b2ee80d5d30fc2a86`).

These grades apply to the requested contracts, not to either product as a whole. No further known weaker behavior was found in these paths. Buffalo intentionally retains its own resource limits and complete-record evidence reducer. It queues one review per committed compaction, whereas the reference can coalesce several pending compactions into one in-memory flag.

## Model parameters

the reference's `planRefinement:892–927` and `reviewAutoRefine:965–1000` deliberately ignore the interactive thinking level and omit reasoning from their `completeSimple` options. The underlying OpenAI transports translate this into their model's off setting where supported.

Buffalo now gives reviewer/planner requests an explicit `reasoning_mode=off`, disables inherited thinking controls on a copied provider configuration, and requests `reasoning_effort=none`. The native subscription provider consults its account model catalog: it chooses `none` when supported, otherwise the least supported effort. Main-agent configuration is never rewritten by this auxiliary resolution. The existing evaluation provider permits this specific auxiliary exception while continuing to reject changes to main-agent or child model/settings. Auxiliary evidence-reduction calls retain the same structured refinement role and policy.

## Persistence and validation

Schema 12 adds request classification and a persisted refinement trigger. Migration classifies historical auxiliary requests, removes their graph membership, reconnects old continuation chains to their trajectory ancestor, and preserves call/attempt/usage history. It does not invent provider calls or billing. Compaction checkpoint identity is derived from the committed event ID, making duplicate admission idempotent.

- Full suite: **439 passed, 9 skipped, 2 existing terminal-test deprecation warnings in 87.70 seconds**. All **24 new behavioral cases** pass.
- New behavioral tests cover public manual triggering, refusal bypass, whole-batch stale-write rejection, automatic false/true decisions, failed/cancelled and extractive compaction, safe-boundary deferral, checkpoint atomicity, restart before/after a checkpoint claim, auxiliary retry/accounting and graph recovery, schema-11 repair, all four state kinds outside top relevance, deterministic overview truncation, wire reasoning parameters, and pinned evaluation settings.
- Existing tests retain their provenance, conflict, crash, recovery and state assertions. Manual test fixtures now expect a planner call without a reviewer; tests specifically about review use automatic triggers. Empty manual planning is decided by the controlled planner response.
- Ruff lint, Ruff formatting, `git diff --check`, and `uv build` all pass. Repository CI uses those Ruff checks, pytest and package build; no mypy/pyright configuration or CI step exists. No additional type checker was introduced.
- The unchanged native bridge was compared byte-for-byte with the validation source and passed `cargo check` plus its executable unit test (1 passed) against Buffalo's pinned Codex revision `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`.
- No live paid-provider requests were made. Provider behavior is covered with controlled model peers and HTTP wire capture; the native bridge source is unchanged.
